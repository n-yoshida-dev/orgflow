# ADR-026: 申請先に選べる組織を、requester role を持つ所属先に限る

- Status: Accepted
- Date: 2026-04-08
- 関連: ADR-005（request の参照方式） / ADR-025（role の付与構造） / ADR-015（tenant 一致の表現）

> **決定**: request 作成時に申請先として選べる internal organization は、current tenant 内で、その user が所属していて、かつ request 作成を許可する role が付与されている組織に限る。

## 背景

ADR-005 で request が申請者と組織を直接参照すると決めたが、「どの組織を申請先に選べるか」は決めていなかった。

制限しないと、current tenant 内の任意の組織へ誰でも申請できる。この状態では業務権限の境界が実質的に存在しないことになる。

## 理由

- 所属していない組織へ申請できてしまうと、承認ルートの決定も監査ログの帰属も意味を失う
- 所属だけでなく role まで見ることで、同じ user が組織ごとに申請可否を変えられる。兼務している組織のうち一部にだけ申請できる、という業務ルールが表現できる
- request 自体は所属関係を参照しない（ADR-005）ため、申請可能かどうかの判定は作成時に一度だけ行い、結果を request の帰属として固定する

## 検討した他の案

- **案A: current tenant 内であれば任意の組織を選べる** — tenant 境界しか効かず、組織単位の業務権限が意味を持たなくなる
- **案B: 所属していることだけを条件とし、role は見ない** — 閲覧目的で所属している組織にも申請できてしまう。所属と申請権限が同じものになる
- **案C: 判定結果として所属関係の id を request に保存する** — どの所属で権限判定したかを残せるが、ADR-005 で避けた「所属関係への参照」を持ち込むことになる

## 受け入れる制約

- 申請時点でどの所属関係によって権限判定したかは request に残らない。監査で追うには当時の所属履歴が別途必要になる
- 申請可能条件は単独の外部キー制約では表現できず、API 側の認可判定に依存する。DB 制約だけでは「所属していない組織への request」を防げない

## 見直す条件

- 代理申請を導入する場合
- 申請時点の所属関係を監査対象として固定保存する必要が出た場合
- 申請可能な組織の条件が role 以外の属性（予算区分、勤務地など）に依存するようになった場合
