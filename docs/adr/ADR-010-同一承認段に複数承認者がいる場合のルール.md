# ADR-010: 同一承認段に複数承認者がいる場合のルール

- Status: Accepted
- Date: 2026-03-24

> **決定**: Phase 1 では、同一承認段に複数承認者がいる場合、誰か1人が承認すればその承認段は完了する。全員承認が必要な場合は承認段を分けて表現する。

## 背景

- 1つの承認段に複数の承認者が存在するケースを Phase 1 でも扱えるようにしたい
- ただし、同一段の完了条件を決めないと、状態遷移、承認処理、テスト方針が曖昧になる
- 全員承認、主担当制、誰か1人で完了など、複数のルール候補がある
- Phase 1 では、複雑さを増やしすぎずに承認フローを説明できる必要があった

## 採用した案

Phase 1 では、同一承認段に複数承認者がいる場合、**誰か1人が承認すればその承認段は完了する** ルールとする。

- 全員承認が必要な場合は、承認段を分けて表現する
- 主担当・副担当の区別は Phase 1 では持たない

## 採用理由

- 状態遷移ロジックを単純に保てる
- 承認完了条件を明快に説明できる
- 実装とテストの難易度を抑えられる
- Phase 1 で重視するのは、複雑な承認制度の網羅ではなく、承認フローを壊さず説明可能にすることだからである

## 不採用案

### 案A: 同一承認段の全員承認を必須にする

- 状態管理が複雑になる
- 途中状態や未承認者の扱いを細かく設計する必要がある
- Phase 1 の範囲に対して重い

### 案B: 主担当 + 副担当を持つ

- 役割定義が増える
- 主担当不在時の扱いなど、追加ルールが必要になる
- Phase 1 の対象を超える

### 案C: ケースごとに完了条件を切り替える

- 柔軟ではあるが、設計・実装・テストが一気に重くなる
- まずは単一ルールで固定した方が説明しやすい

## 受け入れる制約

- 全員承認が必要なユースケースを直接は表現できない
- 主担当・副担当のような役割差分は扱えない
- より複雑な承認制度へは将来拡張が必要になる

## 見直す条件

- 全員承認を直接データで表現する必要が生じた場合
- 主担当・副担当や代理承認などを設計対象に含める場合
- 承認制度の複雑化により、「誰か1人で完了」では業務要件を満たせなくなった場合
