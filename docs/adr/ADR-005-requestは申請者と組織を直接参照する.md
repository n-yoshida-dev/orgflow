# ADR-005: request は申請者 user と internal organization を直接参照する

- Status: Accepted
- Date: 2026-03-24
- 関連: ADR-026（申請先に選べる組織の条件） / ADR-015（tenant 一致の表現） / ADR-007（request の版管理）

> **決定**: request は `applicant_user_id` と `internal_organization_id` を直接持つ。所属関係（`internal_organization_membership`）への参照は持たない。

## 背景

request は「誰が」「どの組織に対して」提出した申請かを保持する必要がある。参照の持ち方には、所属関係の id を1本持つ案と、user と組織をそれぞれ直接持つ案があった。

決めないと、申請後に申請者が異動したときに、過去の request がどこに帰属していたのか追えなくなる。

## 理由

- 所属関係は「現在の所属」を表すため、異動や削除で変化する。request が参照していると、過去の申請の帰属が後から書き換わってしまう
- request が保持すべきなのは申請時点の帰属という不変の事実であり、現在の所属関係ではない
- user と組織を直接持てば、その後の異動に関わらず申請時点の帰属を追跡できる

## 検討した他の案

- **案A: 所属関係の id を1本だけ持つ** — 所属が変更・削除されると参照が壊れるか、参照先の意味が変わる。列は1本で済むが、過去の申請の帰属が可変になる

## 受け入れる制約

- request の列が1本増える
- 「申請時点の所属」と「現在の所属」が乖離していても、request 単体では検知できない
- 申請時にどの所属関係で権限判定したかは request に残らない（ADR-026）

## 見直す条件

- 代理申請を導入し、「操作した人」と「申請の帰属組織」を分けて持つ必要が生じた場合
- 「申請者の所属先」と「経費計上先の組織」を分けて保持する必要が生じた場合
- 申請時点の所属関係そのものを監査対象として固定保存したくなった場合
