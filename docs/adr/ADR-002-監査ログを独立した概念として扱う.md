# ADR-002: 監査ログを独立した概念として扱う

- Status: Accepted
- Date: 2026-03-19
- 関連: ADR-011（audit_log の保持方法）

> **決定**: 監査ログ（audit_log）を、request や approval とは独立した概念として設計する。

## 背景

承認履歴だけでなく、利用者の操作全体を後から追跡する必要がある。

approval は「承認するかどうかの判断」の記録であり、記録される対象も範囲も監査記録とは異なる。ログイン、設定変更、権限付与のような承認以外の操作は approval には現れない。

## 理由

- 承認以外の操作（ログイン、設定変更、role の付与）も同じ仕組みで記録できる
- 「誰が・いつ・何をしたか」を対象の種別によらず同じ形式で追跡できる
- 監査要件を後から足すのではなく、最初から設計に組み込める

## 検討した他の案

- **案A: アプリケーションログのみで対応する** — 出力形式が実装都合で変わり、業務上の証跡として検索・提示できない
- **案B: approval で履歴を兼用する** — 承認以外の操作を表現できない。承認の意味も曖昧になる

## 受け入れる制約

- 設計対象の概念が1つ増える
- 何を監査対象とするかの線引きを別途決める必要がある

## 見直す条件

- イベント駆動設計を導入する場合
- audit_log とイベント履歴の役割を再整理する必要が出た場合
